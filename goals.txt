DONE detail for #16 (b31): Effects drawer tab with a 64-band log-spaced
spectrum, peak-hold caps, dBFS readout and decade axis labels. Hand-rolled
radix-2 FFT (src/Spectrum.swift) after vDSP's split-complex real FFT packing was
found to halve bin numbering; DSP split into a testable SpectrumCore.
tools/test_spectrum/main.swift compiles the production source and passes 52
checks (FFT vs naive DFT, tone->bin at 44.1/48/96 kHz, band mapping, level
scaling, ring wrap, stereo downmix). Found and fixed 3 real bugs: Float->Double
ring read after wrap, unnormalized magnitudes, and a -6 dBFS ceiling that
clipped ordinary material.

DONE detail for #21 (b32): metadata editor in the flyout's Utilities tab. Pure-Swift
ID3v2 reader/writer (src/AudioTags.swift, zero deps) reads v2.2/v2.3/v2.4 with
unsync, extended headers and APIC art, and writes v2.3 preserving every unmanaged
frame; src/TagEditor.swift renders the fields. Only ID3 containers (mp3/mp2/mp1/mpa)
are editable. tools/test_id3/main.swift compiles the shipping source and passes
46/46; the writer was independently cross-checked against a hand-written Python
ID3 parser on a real lame-encoded MP3.

DONE detail for #14 (b33): gapless + crossfade in the flyout's Effects tab.
A second confirm-on cadence AVAudioEngine is pre-started just before the
outgoing track ends (native format path only), so a transition needs no
teardown gap. Options: Off (the proven stop-then-start path, default), Gapless
(0.08 s overlap, incoming starts at full volume) and true crossfades of 2/4/6/8 s
(piecewise-linear node-volume ramps at 20 ms). src/Crossfade.swift holds the
option mapping and fade math as pure code; tools/test_crossfade/main.swift
compiles the shipping source and passes 34/34. Repeat-one, the last track with
repeat off, and the shuffled repeat-all wrap are deliberately left to the normal
end-of-track path (the wrap re-permutes the queue). Pause, seek and stop cancel
an in-flight transition.

DONE detail for #17 (b33): 10-band EQ in the Effects tab. The DSP is a single
AVAudioUnitEQ inserted between each in-app engine's main mixer and its output
node (native AVAudioFile, embedded AVAudioSourceNode, and MIDI sequencer paths),
so every track through those engines passes through the same live-adjustable
filters. The AVPlayer fallback and AVMIDIPlayer paths cannot host an AU insert
and stay flat (documented in the UI hint). Bands are the classic ten-slopers
31 Hz..16 kHz, 1 octave apart, Q 1.0, ±12 dB; gains/state persist (ac_eq_active,
ac_eq_gains). src/Equalizer.swift pairs the Equalizer state object with a
testable EqualizerCore: RBJ peaking-biquad coefficients + a unit-circle
frequency response. tools/test_equalizer/main.swift compiles the shipping source
and passes 24/24 (band table, clamping, guard rails, 0 dB identity across the
range, boost peaks at the target gain and returns to unity far away, cut is the
exact reciprocal of boost, clamped -12 dB floor, band 1 octave away is smaller).

DONE detail for #20 (b41): DTS Core is decoded by a vendored pure-Rust library,
oxideav-dts 0.0.2 (MIT, Mark Karpeles/OxideAV). The crate is built as a
staticlib under --no-default-features (its optional oxideav-core registry dep is
not vendored; the four registry integration tests are gated behind the
"registry" feature via required-features so the offline no-default build is
clean) and reached from the C decoders through a tiny extern "C" shim
(vendored/dts/src/ffi.rs + dts_ffi.h). build.sh / build_tools.sh gained a
per-arch cargo step and every C tool that links the decoder archive also links
the resulting liboxideav_dts.a. New DEC_KIND_DTS in vendored/decoders/decoders.c
sniffs the 4-byte DTS sync (raw BE/LE + 14-bit) and decodes the Core stream to
interleaved int32 at native rate; the primaries arrive in transmission order
with the LFE plane trailing, so an arrangement-aware multichannel->stereo downmix
(AMODE Table 5-4: front L/R unity, centre/surround -3 dB, rear pairs -6 dB, LFE
halved, AMODE 3 sum/difference decoded, AMODE 1 dual-mono and >15 user-defined
fall back to the first two planes) runs before the shared pcm_to_stereo resampler
(48 kHz -> 44.1 kHz), so DTS gets the same SEEK/END_OF_STREAM/duration behaviour
as the other embedded decoders. "dts"/"dtshd" moved from the unsupported list to
embeddedExtensions. tools/test_dts.c links the shipping decoder and checks five
fixtures (plain stereo, D10, joint, termination, 5.1+LFE) against independent
ffmpeg-derived references: the reconstructed waveform is shape-identical to the
reference (Pearson correlation 1.000000 on every channel — the DTS output gain is
implementation-defined, so comparison is scale-invariant, matching the crate's
own black-box test), plus resampled length, native-rate read length, seek,
overshoot-EOF, probe-duration and reject-truncated cases: 74/74.

DONE detail for #24 (b42): WMA v1/v2 is decoded by a vendored pure-Rust library,
oxideav-wma 0.0.4 (MIT, Mark Karpeles/OxideAV) — the only shippable path, since
every existing WMA decoder (ffmpeg wmadec/wmaprodec, Rockbox libwma, ScummVM,
Echo C#) is GPL/LGPL and cannot be shipped under the permissive-only policy. The
crate covers the *codec payload only*, not the ASF container, and its own tests
shell out to ffmpeg to unwrap ASF — so the real work was a minimal ASF reader in
the C shim (vendored/wma/src/ffi.rs + wma_ffi.h), 702 lines, no external deps.
It walks the ASF Header Object by object count (some files, e.g. streamed
excerpts, carry a zero header-size field), finds the Data Object by GUID rather
than assuming offset 0, reads the packet size from the File Properties Object,
and reassembles each packet's single- or multi-payload body (spec §5.2.3.3:
Payload Flags byte -> number-of-payloads + length-type, then per payload the
stream/media-object numbers, offset, replicated-data length+data, and payload
length+data) into `block_align` codec packets. Those feed the crate's direct
codec path (StreamConfig -> PacketAssembler -> FrameParser -> BlockSynth),
bypassing the oxideav-core registry entirely (the crate is vendored with no
[dependencies]; only lib.rs + registration.rs touched core and registration was
dropped). The shim hands back interleaved *stereo* int32 at native rate (mono
duplicated), so DEC_KIND_WMA in decoders.c is a straight pcm_to_stereo resample —
same SEEK/END_OF_STREAM/duration behaviour as the other embedded decoders.
"wma"/"asf" moved from the unsupported list to embeddedExtensions.
tools/test_wma.c links the shipping decoder over six real ASF/WMA fixtures
(twins 1.4 s newscast excerpt, sample15 15 s, example 36 s — all stereo — plus
three mono WMAv2 44.1 kHz files: 5 s, 15 s, 30 s from samplefile.com) and checks
open, stereo 44100 output, duration vs. the header, decoded length, non-silence,
peak in (0,1], sample-accurate seek, and mono->stereo duplication (L == R): 86/86.
Validation is plausibility-based because no local ffmpeg exists to produce
reference PCM; peak/RMS/length and
non-clipping counts are all consistent with real content. NOTE: WMA is not
bit-exact to any reference decoder — the crate itself lists black-box-fitted
rows and unvalidated WMA v1, so this is a straightforward (not reference-grade)
implementation.

DONE detail for #23 (b40): MIDI sound bank + instrument, src/MIDIBank.swift.
AVMIDIPlayer *does* accept a bank at construction (`soundBankURL:`), so the
proven Engine D can load a user SoundFont/DLS without the fragile sampler path.
MIDIBankCore (pure, no AVFoundation/UserDefaults) holds the 128-name General
MIDI table, bank sniffing (RIFF+"sfbk"=SF2, RIFF+"DLS "=DLS; also by extension)
and a full SMF walker that reports/handles program changes (running status,
meta and sysex aware). smfInjectingProgramChange() prepends a delta-0 program
change on the first channel of every track that names no instrument, byte-for-
byte preserving the rest so multi-instrument files keep their own arrangement
and the operation is idempotent. startEngineD keeps its original fast path when
no bank/override is set, otherwise uses the in-memory SMF (needed for .rmi and
for injection) with the resolved bank; a custom bank that fails to load falls
back to the system synth. startEngineE loads the resolved bank (custom bank 0/0
+ chosen program, or the system GS DLS at 0x79/0x00) and honours the override
for files with no program change. Settings gains a MIDI section: bank name +
Choose…/Use system (NSOpenPanel filtered to .sf2/.dls, magic-checked) and a GM
instrument picker + "play files without an instrument using this one" toggle;
the bank path and program persist (ac_midi_bank / ac_midi_program /
ac_midi_override), and a moved/deleted bank silently reverts to the system. The
system GS DLS path was centralised here (Player's old gsBankURL is gone).
tools/test_midibank/main.swift compiles the shipping source and passes 40/40
(name table, clamping, extension + magic sniffing, SMF detection with running
status, injection growth/placement/idempotence/body preservation, multi-track,
malformed rejects, program clamp).
