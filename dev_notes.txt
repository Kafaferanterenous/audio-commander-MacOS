
--- UI work in progress (not a release; started after v0.6.3) ---
Four requested UI changes, done in small verified steps. Backup taken first
before touching anything: archive/audio-commander-src-b31-backup-*.tar.gz (31 MB,
1614 entries) and archive/dist-backup-*/AudioCommander.app (signature verifies).
archive/ is gitignored — it is a local safety net, not source.

1. Settings moved from a modal sheet into the flyout.
   - DrawerTab gained .settings, so the picker is Library/Effects/Utilities/
     Settings.
   - Tab selection moved from @State on InspectorDrawer to
     CommanderStore.drawerTab, because something outside the drawer (the gear,
     the Settings… menu item) now has to select a tab.
   - SettingsSheet -> SettingsPanel: dropped the modal width, gradient backdrop
     and Close button; wrapped the body in a ScrollView since the full settings
     list is taller than the flyout. Menu bar Settings… routes to the same tab,
     so settings live in exactly one place.
2. Top button cluster cleaned up.
   - The pane toggle button was removed outright: it overlapped the left pane's
     "Left" header and, with the gear opening the flyout, it had no job left.
   - Mini player moved right to sit beside the gear.
   - The gear now toggles — closes the flyout when Settings is already showing —
     because it is the only toggle left. Both buttons tint with the accent when
     their state is active (the gear did not before).
3. Sleep timer split over two rows in Utilities. Five segments across a 320pt
   drawer were unreadable, and a segmented Picker cannot wrap itself, so the
   choices are now a 3+2 grid of buttons drawn to look like segments. Needed a
   compact label: added "sleepMinutesShort" ("60 min") in all four languages
   alongside the existing full "sleepMinutes", plus SleepTimerOptions.shortLabel.
   The old label() is still used by the context menu.
4. Drawer widened 320 -> 360pt, which the four-tab picker and the timer grid both
   want. Flagged to the user as easily reverted.

STILL TO DO (from the same request list):

  closing the big window with its red button quits the app entirely. That means
  removing the applicationShouldTerminateAfterLastWindowClosed exception at
  ContentView.swift:43, which deliberately keeps the app alive so the mini player
  can outlive the main window. Window size is already persisted via ac_win_frame
  and restored at launch, so "remembers the size" should need no new code — verify
  rather than rebuild.
- Dock activation while the mini player is showing should reveal the big window
  (planned behaviour, agreed in principle).
- NOT STARTED, raised with the user: the pane-swap button sits centered at
  offset(y: 26) and is the other round button overlaying content. Offered to
