AUDIOCOMMANDER (macOS PORT) - DEV NOTES
=======================================

Project:   AudioCommander - dual-pane audio browser/player
Version:   v0.1 (planned)
Started:   2026-08-22
Location:  opencode_mac/002_2026_08_22_AudioCommander
Reference: other/Linux/audiocommander-linux-experimental (C11 + GTK3, read-only)

--------------------------------------------------
LEARNED FROM LINUX ORIGINAL
--------------------------------------------------
- Dual-pane audio browser: independent panes, sortable listings,
  active-pane operations
- Formats: WAV/MP3/M4A/FLAC/WMA/Ogg/Opus/ALAC/MIDI/MOD/S3M/XM
  (FFmpeg/libav decode; libopenmpt for trackers)
- Metadata + duration display, directory audio totals, sequential Play All
- No silent overwrite; recoverable Trash deletion; strong warnings before
  permanent/removable-media deletion
- Copy progress dialog only after 600ms (fast copies show nothing)
- Localization: EN / zh-CN / IT / PL
- Pastel default theme + eight external .skn palettes -> CSS
- Settings at $XDG_CONFIG_HOME/audiocommander/settings.ini

--------------------------------------------------
macOS PORT PLAN
--------------------------------------------------
- Language: Swift + SwiftUI (AppKit where needed) - zero external deps
- Audio playback: AVFoundation (built-in; covers most formats natively;
  tracker formats MOD/S3M/XM likely dropped or via bundled C lib if ever)
- File ops: FileManager + NSURLVolumeEnumerator; Trash via
  FileManager.trashItem (native recoverable delete)
- Metadata: AVAsset metadata (no FFmpeg needed for common formats)
- Settings: UserDefaults + JSON in ~/Library/Application Support/
- Localization: Apple .strings mechanism (EN first, then zh-CN/IT/PL)
- Theme: follow system appearance + pastel accent palette
- Packaging: proper .app bundle, universal binary target possible

- NEW vendored C layer (vendored/, compiled INTO binary, zero external deps
  convention preserved):
  * DUMB 2.0.3 (kode54 fork, permissive license, vendored/dumb/license/)
    -> tracker modules: MOD S3M XM IT 669 AMF AMS DSM FAR MTM OKT PSM PTM
    STM ULT via dumb_read_any (memory loader). Loop callback forces play-
    once so looping modules terminate.
  * stb_vorbis (public domain, vendored/stb/) -> OGG Vorbis incl. seek.
  * decoders.c/h: unified pull-decoder API (dec_open/render/seek/duration/
    probe_duration), all formats normalized to interleaved stereo f32
    @44100. Handles are void* so the header imports cleanly into Swift
    (clang importer skips incomplete structs - learned the hard way).
    Custom VOC parser included: blocks 0x01/0x03/0x09, u8+s16 PCM, linear
    resample to 44100; ADPCM subformats skipped.

  A AVAudioFile native -> B AVPlayer fallback -> C embedded PullDecoder on

  Routing by extension (AudioFormats.route); native route falls through
  A->B->C; embedded route tries C then B; MIDI goes straight to D.
- DURATIONS for new formats load async like native ones: dec_probe_duration
  for embedded files; throwaway AVMIDIPlayer for .mid. NOTE: duh_get_length
  is a "suitable stop point" per DUMB docs - decaying module tails can

- TEST TOOLING: tools/gen_fixtures.py (VOC+MID writers), gen_modules.py

  probe-consistent. Swift wrapper exercised same path via CLI build.
  XM gotcha encoded in gen_modules.py: packed columns need bit7 set (0x87);

- BUILD: build.sh compiles vendored C per arch (-mmacosx-version-min=13.0)

=== 2026-09-23 (part 3) — FIX: TRACKER PLAYBACK ~2.2x SLOW (v0.6 b10) ===
- USER REPORT (real mac): .mod/.s3m/.it/.xm play but SLUGGISH/slowed down;
  mp3/m4a/mid fine.
- ROOT CAUSE (vendored/decoders/decoders.c): duh_render() delta_time arg
  was (float)OUT_RATE/65536.0f — the RECIPROCAL of the correct value.
  DUMB's delta_time is "65536ths of a second per output sample", so it must
  be 65536.0f/OUT_RATE (1.4861 @44100), not OUT_RATE/65536 (0.6729).
  Wrong delta -> each output sample advances too little module clock ->
  same music stretched over 2.2x more frames -> slows playback by 2.2x.
- PROOF (fixture harness, dumb render): fixture test.mod (duh_len 0.240s):
  delta=0.6729 -> 23361 frames (=0.530s, 2.2x stretched);
  delta=1.4861 -> 10578 frames (=0.240s EXACT match). Applied.
- CHANGE: new DUMB_DELTA (65536.0f/OUT_RATE) used in both DUMB render
  (dec_render) and DUMB seek (dec_seek). OGG/VOC paths untouched (they use
  their own resamplers).
- VERIFIED via dec_open/dec_render full-render harness (real decoder stack):
  test.mod 0.240s/10578fr, test.s3m 2.575s/113570fr, test.xm 8.628s/380489fr,
  loud.mod/xm 7.676s/338500fr — ALL now exactly match duh_len durations.
  tools/test_decoders.c: S3M/VOC/loud.mod PASS (mid-seek rms sane, probe
  consistent). NOTE: test.mod/test.xm "silent stream" FAILs are PRE-EXISTING
  fixture artifacts (near-silent byte-written fixtures) — identical under
  old delta; not a regression.
- Info.plist CFBundleVersion 9 -> 10. Needs a real-Mac ear check that
  modules now play at correct tempo.

=== 2026-09-23 (part 4) — FIX: MIDI PAUSE/RESUME STUTTER+STOP (v0.6 b11) ===
- USER TEST: tracker fix CONFIRMED by ear (real mac). Item 2 (MIDI
  resume-from-position) FAILS: pause->resume stutters then stops.
- ROOT CAUSE (Engine D, AVMIDIPlayer): pause used stop(); the resume path set
  player.currentPosition BEFORE play() while the player was stopped — macOS
  AVMIDIPlayer commonly IGNORES the position on a stopped player and restarts
  at 0 -> audible jump/stutter + wrong timeline. Compounding: the 0.25s
  ticker kept writing player.currentPosition into currentTime while paused
  (stopped player reports 0), so currentTime dropped to 0 after every pause —
  scrambling the display, previous() restart logic, and the midiFinished()
  near-end check (could skip auto-advance).
- CHANGES (src/Player.swift, Engine D only):
  1) Resume now: play() first, then re-set currentPosition while PLAYING
     (both pre- and post-play set, so either macOS behavior is covered).
  2) midiFinished() end-check now reads player.currentPosition live instead
     of the (stale/zeroed) published currentTime.
  3) Ticker .midi branch only updates currentTime while player.isPlaying, so
     pausing no longer zeroes the displayed position.
- Pause->resume of .mid/.rmi is inherent to stop()/restart (DLS tail) — small
  click is expected; the stutter-at-0 and mid-song stop should be gone.
- Info.plist CFBundleVersion 10 -> 11 (b11).
- Needs ear re-test: pause->resume on a long .mid; seek-while-paused; seek
  position retained after resume.

b27 — GOAL #11: WAVPACK (.wv)  [DONE, built, awaiting real-Mac verification]
- LICENCE: libwavpack 5.9.0 (tag 5.9.0, github.com/dbry/WavPack) is BSD
  2-Clause — fits the permissive-only policy. Vendored under vendored/wavpack/
  (include/wavpack.h, src/*.c, COPYING). Built with -DENABLE_LEGACY so the old
  32-bit reader API and v3 .wvk files work. open_filename.c is NOT vendored
  (we feed it memory, not filenames) and threads are left off.
- INTEGRATION (vendored/decoders/decoders.c): DEC_KIND_WAVPACK, detection on the
  "wvpk" block magic at offset 0, in-memory WavpackStreamReader, 32-bit int ->
  /2147483648.0 -> float, native rate -> shared 44100 resampler, mono duplicated
  to both outputs, >2 channels downmixed to the first two, seek via
  WavpackSeekSample64 into the existing dec_seek.
- THREE REAL BUGS found by testing (all would have shipped):
  1. SEEK WAS SILENTLY BROKEN. libwavpack's set_pos_abs/set_pos_rel callbacks
     follow the fseek() convention: 0 = SUCCESS, nonzero = failure. My reader
     returned 1 on success, so every internal find_header() call bailed out
     immediately and WavpackSeekSample64() always returned FALSE — seeking did

- DECODER — vendored/decoders/decoders.c, new DEC_KIND_OGGFLAC:
  * libFLAC owns the Ogg framing, so only a raw-memory read/seek/tell/length/eof
    callback set is needed (of_read..of_eof); libogg's framing.c does the rest.
  * of_write converts libFLAC's per-frame channel pointers to the decoder's
    planar float buffers and pushes them through the SAME pcm_to_stereo helper
    WavPack/Vorbis/DUMB use, so Ogg FLAC inherits the shared resampler and the
    shared SEEK/END_OF_STREAM handling for free.
  * of_metadata is load-bearing and not obvious: libFLAC only publishes
    sample_rate/channels/blocksize to its getters once the first AUDIO frame is
    decoded, so STREAMINFO is the only way to know the stream's shape at open
    time. Duration comes from STREAMINFO total_samples.
  * of_error latches of_failed so a mid-stream FLAC error ends playback cleanly
    rather than spinning.
  * oggflac_teardown clears of_stream.d BEFORE freeing it, so no late libFLAC
    callback can touch freed memory.
- PROBE ORDER — dec_open() now sniffs the Ogg mapping FIRST, before stb_vorbis:
  ogg_is_flac() is a cheap exact check on page 0 (see the comment for the header
  layout). Two encodings are accepted: the native 0x7F "FLAC" magic that libFLAC's
  own Ogg encoder writes, and the Xiph "\x01FLAC" mapping header other tools
  write. This matters because stb_vorbis_open_memory copies the whole file into
  its own buffer and builds a hash table — pure waste for every .oga.
  The unguarded oggflac_open() call is KEPT after the vorbis attempt as a
  fallback, so an unrecognized-but-still-FLAC mapping degrades to "decodes"
  rather than to "unsupported". I wrote the sniff wrong on the first attempt
  (assumed the mapping packet was at offset 5, then 27); the fixtures caught it
  immediately and the real layout is the repacketized native magic at
  27 + segment_count. Tests are why this was cheap to fix.

- Effects drawer tab now shows a live log-spaced spectrum (64 bands, 30 Hz–16 kHz)
  with peak-hold caps, a dBFS readout and decade axis labels.
- FFT: started on vDSP.FFT<DSPSplitComplex> and got bin numbering off by 2x
  (1 kHz peaked at bin 23 instead of 46 at 44.1 kHz/2048). Cause is vDSP's
  split-complex real FFT packing ([Re(0), Re(N/2), Re(1), Im(1), ...]) plus the
  wrapper's interleaved input — a real signal fed as 2^L reals lands on even
  indices only, halving apparent bin numbers. Replaced with a hand-rolled
  iterative radix-2 Cooley-Tukey (Radix2FFT, separate real/imag planes, ~80
  lines) because its bin numbering can be checked against a naive DFT, which is
  exactly the property vDSP's packing obscured. Validated vs naive DFT for
  n = 8/16/64/256 (max error <= 6e-13 relative).
