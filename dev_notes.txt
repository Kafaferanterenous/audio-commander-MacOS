AUDIOCOMMANDER (macOS PORT) - DEV NOTES
=======================================

Project:   AudioCommander - dual-pane audio browser/player
Version:   v0.1 (planned)
Started:   2026-08-22
Location:  opencode_mac/002_2026_08_22_AudioCommander
Reference: other/Linux/audiocommander-linux-experimental (C11 + GTK3, read-only)

--------------------------------------------------
LEARNED FROM LINUX ORIGINAL
--------------------------------------------------
- Dual-pane audio browser: independent panes, sortable listings,
  active-pane operations
- Formats: WAV/MP3/M4A/FLAC/WMA/Ogg/Opus/ALAC/MIDI/MOD/S3M/XM
  (FFmpeg/libav decode; libopenmpt for trackers)
- Metadata + duration display, directory audio totals, sequential Play All
- No silent overwrite; recoverable Trash deletion; strong warnings before
  permanent/removable-media deletion
- Copy progress dialog only after 600ms (fast copies show nothing)
- Localization: EN / zh-CN / IT / PL
- Pastel default theme + eight external .skn palettes -> CSS
- Settings at $XDG_CONFIG_HOME/audiocommander/settings.ini

--------------------------------------------------
macOS PORT PLAN
--------------------------------------------------
- Language: Swift + SwiftUI (AppKit where needed) - zero external deps
- Audio playback: AVFoundation (built-in; covers most formats natively;
  tracker formats MOD/S3M/XM likely dropped or via bundled C lib if ever)
- File ops: FileManager + NSURLVolumeEnumerator; Trash via
  FileManager.trashItem (native recoverable delete)
- Metadata: AVAsset metadata (no FFmpeg needed for common formats)
- Settings: UserDefaults + JSON in ~/Library/Application Support/
- Localization: Apple .strings mechanism (EN first, then zh-CN/IT/PL)
- Theme: follow system appearance + pastel accent palette
- Packaging: proper .app bundle, universal binary target possible

    -> tracker modules: MOD S3M XM IT 669 AMF AMS DSM FAR MTM OKT PSM PTM

=== 2026-09-23 (part 3) — FIX: TRACKER PLAYBACK ~2.2x SLOW (v0.6 b10) ===
- USER REPORT (real mac): .mod/.s3m/.it/.xm play but SLUGGISH/slowed down;
  mp3/m4a/mid fine.
- ROOT CAUSE (vendored/decoders/decoders.c): duh_render() delta_time arg
  was (float)OUT_RATE/65536.0f — the RECIPROCAL of the correct value.
  DUMB's delta_time is "65536ths of a second per output sample", so it must
  be 65536.0f/OUT_RATE (1.4861 @44100), not OUT_RATE/65536 (0.6729).
  Wrong delta -> each output sample advances too little module clock ->
  same music stretched over 2.2x more frames -> slows playback by 2.2x.
- PROOF (fixture harness, dumb render): fixture test.mod (duh_len 0.240s):
  delta=0.6729 -> 23361 frames (=0.530s, 2.2x stretched);
  delta=1.4861 -> 10578 frames (=0.240s EXACT match). Applied.
- CHANGE: new DUMB_DELTA (65536.0f/OUT_RATE) used in both DUMB render
  (dec_render) and DUMB seek (dec_seek). OGG/VOC paths untouched (they use
  their own resamplers).
- VERIFIED via dec_open/dec_render full-render harness (real decoder stack):
  test.mod 0.240s/10578fr, test.s3m 2.575s/113570fr, test.xm 8.628s/380489fr,
  loud.mod/xm 7.676s/338500fr — ALL now exactly match duh_len durations.
  tools/test_decoders.c: S3M/VOC/loud.mod PASS (mid-seek rms sane, probe
  consistent). NOTE: test.mod/test.xm "silent stream" FAILs are PRE-EXISTING
  fixture artifacts (near-silent byte-written fixtures) — identical under
  old delta; not a regression.
- Info.plist CFBundleVersion 9 -> 10. Needs a real-Mac ear check that
  modules now play at correct tempo.

=== 2026-09-23 (part 4) — FIX: MIDI PAUSE/RESUME STUTTER+STOP (v0.6 b11) ===
- USER TEST: tracker fix CONFIRMED by ear (real mac). Item 2 (MIDI
  resume-from-position) FAILS: pause->resume stutters then stops.
- ROOT CAUSE (Engine D, AVMIDIPlayer): pause used stop(); the resume path set
  player.currentPosition BEFORE play() while the player was stopped — macOS
  AVMIDIPlayer commonly IGNORES the position on a stopped player and restarts
  at 0 -> audible jump/stutter + wrong timeline. Compounding: the 0.25s
  ticker kept writing player.currentPosition into currentTime while paused
  (stopped player reports 0), so currentTime dropped to 0 after every pause —
  scrambling the display, previous() restart logic, and the midiFinished()
  near-end check (could skip auto-advance).
- CHANGES (src/Player.swift, Engine D only):
  1) Resume now: play() first, then re-set currentPosition while PLAYING
     (both pre- and post-play set, so either macOS behavior is covered).
  2) midiFinished() end-check now reads player.currentPosition live instead
     of the (stale/zeroed) published currentTime.
  3) Ticker .midi branch only updates currentTime while player.isPlaying, so
     pausing no longer zeroes the displayed position.
- Pause->resume of .mid/.rmi is inherent to stop()/restart (DLS tail) — small
  click is expected; the stutter-at-0 and mid-song stop should be gone.
- Info.plist CFBundleVersion 10 -> 11 (b11).
- Needs ear re-test: pause->resume on a long .mid; seek-while-paused; seek
  position retained after resume.
