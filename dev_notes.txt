AUDIOCOMMANDER (macOS PORT) - DEV NOTES
=======================================

Project:   AudioCommander - dual-pane audio browser/player
Version:   v0.1 (planned)
Started:   2026-08-22
Location:  opencode_mac/002_2026_08_22_AudioCommander
Reference: other/Linux/audiocommander-linux-experimental (C11 + GTK3, read-only)

--------------------------------------------------
LEARNED FROM LINUX ORIGINAL
--------------------------------------------------
- Dual-pane audio browser: independent panes, sortable listings,
  active-pane operations
- Formats: WAV/MP3/M4A/FLAC/WMA/Ogg/Opus/ALAC/MIDI/MOD/S3M/XM
  (FFmpeg/libav decode; libopenmpt for trackers)
- Metadata + duration display, directory audio totals, sequential Play All
- No silent overwrite; recoverable Trash deletion; strong warnings before
  permanent/removable-media deletion
- Copy progress dialog only after 600ms (fast copies show nothing)
- Localization: EN / zh-CN / IT / PL
- Pastel default theme + eight external .skn palettes -> CSS
- Settings at $XDG_CONFIG_HOME/audiocommander/settings.ini

--------------------------------------------------
macOS PORT PLAN
--------------------------------------------------
- Language: Swift + SwiftUI (AppKit where needed) - zero external deps
- Audio playback: AVFoundation (built-in; covers most formats natively;
  tracker formats MOD/S3M/XM likely dropped or via bundled C lib if ever)
- File ops: FileManager + NSURLVolumeEnumerator; Trash via
  FileManager.trashItem (native recoverable delete)
- Metadata: AVAsset metadata (no FFmpeg needed for common formats)
- Settings: UserDefaults + JSON in ~/Library/Application Support/
- Localization: Apple .strings mechanism (EN first, then zh-CN/IT/PL)
- Theme: follow system appearance + pastel accent palette
- Packaging: proper .app bundle, universal binary target possible

- FORMAT SUPPORT PLAN (user requirement: old Android phone files):
  Native AVFoundation: mp3/m4a/aac/wav/aiff/flac/alac/caf/3gp/3g2/AMR

v0.2 (2026-08-22)
- Milestone: playback engine.
- DUAL-ENGINE design (src/Player.swift):
  * Engine A: AVAudioEngine + AVAudioPlayerNode + AVAudioFile -
    native decode for wav/aiff/mp3/m4a/aac/flac/alac/caf. Segment
    scheduling used for seek; position polled via playerTime +
    scheduledStartFrame every 0.25s ticker.
  * Engine B: AVPlayer fallback - QuickTime container coverage
    (3gp/3g2/amr and anything ExtAudioFile can't open). Periodic time
    observer for position, AVPlayerItemDidPlayToEndTime for advance,
    3s watchdog skips files that never start.
  * Engine choice per track at play time (A first, B fallback).
- QUEUE: double-click audio file -> plays it then rest of that pane's
  audio files in sort order ("Play all" button does the same from top).
  Auto-advance stops after last track; manual prev/next wrap. Previous
  restarts current track if >3s in. Broken files skipped with note;
  all-broken queue aborts with message (no infinite skip loop).
- TRANSPORT BAR (bottom, full width): prev/play-pause/next, title +
  "from X pane" + playback notes, elapsed/total mono digits, seek
  slider (clamped binding), volume slider (engine mainMixer / player).
- VERIFIED: universal build OK (1.9 MB), launched, process stable.

KNOWN LIMITS v0.2:
- OGG Vorbis/Opus still not decodable (needs embedded stb_vorbis -
  planned as v0.2.x patch if user needs OGG).
- AMR-NB/WB depends on CoreAudio decoder availability on this OS;
  untested until user supplies a real phone file.

- LOCALIZATION EN/PL/IT/zh-CN (English default, persisted):
  all UI strings incl. dynamic messages through AppSettings.t/tf.
- CENTER DIVIDER: visible themed line - 5px palette divider base +

- BUG FIX poem.3ga (user sample analyzed with afinfo/xxd): standard

  was "3ga" missing from accepted extensions so it was never flagged

  AVAudioFile may reject container -> AVPlayer fallback handles it.

v0.4 (2026-08-24)
- Milestone: EMBEDDED DECODER STACK - inbuilt playback for tracker modules,
  OGG Vorbis, Creative VOC and MIDI (user request: s3m/xm/mod/voc/mid "and
  as many as possible").
- NEW vendored C layer (vendored/, compiled INTO binary, zero external deps
  convention preserved):
  * DUMB 2.0.3 (kode54 fork, permissive license, vendored/dumb/license/)
    -> tracker modules: MOD S3M XM IT 669 AMF AMS DSM FAR MTM OKT PSM PTM
    STM ULT via dumb_read_any (memory loader). Loop callback forces play-
    once so looping modules terminate.
  * stb_vorbis (public domain, vendored/stb/) -> OGG Vorbis incl. seek.
  * decoders.c/h: unified pull-decoder API (dec_open/render/seek/duration/
    probe_duration), all formats normalized to interleaved stereo f32
    @44100. Handles are void* so the header imports cleanly into Swift
    (clang importer skips incomplete structs - learned the hard way).
    Custom VOC parser included: blocks 0x01/0x03/0x09, u8+s16 PCM, linear
    resample to 44100; ADPCM subformats skipped.
- PLAYER: now four engines (src/Player.swift):
  A AVAudioFile native -> B AVPlayer fallback -> C embedded PullDecoder on
  an AVAudioSourceNode render block (NSLock-guarded; pause=silence flag,
  seek=deferred request consumed by render thread, EOF flag consumed by
  ticker) -> D AVMIDIPlayer (native CoreAudio/DLS synth, soundBankURL nil).
  Routing by extension (AudioFormats.route); native route falls through
  A->B->C; embedded route tries C then B; MIDI goes straight to D.
- DURATIONS for new formats load async like native ones: dec_probe_duration
  for embedded files; throwaway AVMIDIPlayer for .mid. NOTE: duh_get_length
  is a "suitable stop point" per DUMB docs - decaying module tails can
  render longer than shown duration (by design, kept for instant probing).
- TEST TOOLING: tools/gen_fixtures.py (VOC+MID writers), gen_modules.py
  (audible ProTracker MOD + FastTracker II XM written byte-by-byte),
  test_decoders.c harness + OpenMPT repo test.mod/s3m/xm fixtures.
  VERIFIED: MOD/XM/VOC/S3M open, render full length non-silent, mid-seek,
  probe-consistent. Swift wrapper exercised same path via CLI build.
  XM gotcha encoded in gen_modules.py: packed columns need bit7 set (0x87);
  instrument extra header = 214 bytes incl. 96-byte note map.
- BUILD: build.sh compiles vendored C per arch (-mmacosx-version-min=13.0)
  into libdecoders.a (~500KB/slice), swiftc links it with
  -import-objc-header src/Bridge.h. Universal app now 3.2 MB. v0.4 b7.
- KNOWN LIMITS v0.4:
  * MIDI: AVMIDIPlayer has no volume property (slider inert for .mid) and
    no pause API - pause implemented as stop()+resume at currentPosition;
    resume-from-position untested by ear yet. RMID (.rmi) not routed.
  * Opus-in-Ogg not decodable by stb_vorbis (falls to skip-with-note).
  * WMA/APE/WavPack/DSD still listed but undecodable (would need FFmpeg-
    scale effort; deliberately out of scope).
  * VOC ADPCM variants ignored silently.

v0.5 (2026-08-25)
- Milestone: outstanding-goals sweep minus listen tests - trash deletion,
  F5/F6 shortcuts, .skn palette import.
- DELETE-TO-TRASH: TransferManager.Mode gained .trash -> FileManager.
  trashItem (recoverable, Trash resolves name clashes; no uniquing pass).
  New per-pane toolbar trash button (mirrored styling, enabled when
  selection non-empty), overlay + result message reuse ("Trashed %d
  item(s)"). SAFETY per porting rules: if the currently playing track is
  in the selection, playback is stopped BEFORE trashing.
- F5/F6 SHORTCUTS (Linux parity): CommanderStore now a shared singleton
  (ContentView uses @ObservedObject) so app-menu commands can reach it.
  Active-pane tracking: @FocusState on each pane List + onActivate hook
  fired from PaneState.open() (row clicks) -> store.activeSide; defaults
  to left pane. F5 = copy active->other, F6 = move active->other.
  GOTCHA: .function KeyboardShortcut modifier is deprecated in macOS 12+
  and reserved for system apps -> built KeyEquivalent from function-key
  Unicode scalars (NSF5FunctionKey 0xF708 / NSF6FunctionKey 0xF709 via
  small KeyEquivalent(functionKey:) helper). Bonus: Cmd+Delete trashes
  the active selection.
- .SKN PALETTE IMPORT (Linux spec): src/Skin.swift ports skin.c semantics -
  INI [Skin] Format=1 + twelve #RRGGBB colors under [Colors]; all keys
  required or file rejected (falls back to built-in theme). Mapping:
  Window -> bg gradient (+5% lighten top), Control -> card fill,
  Border -> divider, Selection -> accent, HotBorder -> folder tint,
  colorScheme from Window luminance. Settings sheet gained Skins section:
  Import .skn... (fileImporter w/ security-scoped URL handling, dynamic
  UTType for extension), imported list w/ swatch + select + remove;
  skins persist in ~/Library/Application Support/AudioCommander/Skins/
  and are rescanned at launch; picking a built-in swatch clears the
  selected skin. AppSettings.palette now returns effective palette.
- LOCALIZATION: trashSel/trashedDone/skinsLabel/importSkin/skinBad/
  noSkins/removeSkin added in EN/PL/IT/zh-CN.
- VERIFIED: universal build OK (3.5 MB); parser harness: valid .skn
  parses correct hex/luminance, truncated file rejected; seeded Steel
  Blue.skn into skins dir, launched, process stable >20s, no crash
  reports, clean SIGTERM exit.
